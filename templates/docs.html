Install & start (Windows)

py -3 -m venv venv
venv\Scripts\activate
pip install -r requirements.txt
python app.py

Open http://127.0.0.1:5000, register an account and upload a project. The database and all uploaded workspaces live in the instance/ folder and are created automatically. Upgrading an existing install is automatic: additive migrations run at startup and never reset data (python -m deadcodex.migrations runs them manually).

Optional environment variables: SECRET_KEY (otherwise one is generated into instance/secret_key), DEADCODEX_GITHUB_TOKEN (server-wide fallback token), FLASK_DEBUG=1.

ZIP & GitHub import

Both routes produce the same stored project and feed the same analyzer. Uploaded code is only read as text - never executed, imported or built.

  • ZIP: the type, integrity and size are checked; entries with path traversal (ZIP-Slip), absolute paths, symlinks, special files, encrypted entries, duplicate names or suspicious compression ratios are rejected with a clear message. A single top-level folder is detected automatically as the project root.
  • GitHub: paste a repository URL (optionally a branch and sub-folder). The exact commit is recorded. Private repositories need a token saved under Settings; it is encrypted at rest and only sent to api.github.com. Invalid URLs, missing/private repos, bad branches, rate limits and network failures each produce a specific error.

Reading a report

Each finding shows file, line, snippet, category, severity and confidence, plus an expandable explanation: why it is a problem, the evidence found, consequences, recommendation, a before/after view and whether it can be fixed automatically.

  • Confirmed - established by the code structure and a project-wide search with no counter-evidence.
  • Potential - might still be used dynamically (reflection, string lookups, public API, framework conventions). Treat as a lead.

Search and filters (category, certainty, severity, fix mode, review state, minimum confidence) are applied on the server. Export JSON downloads the full persisted report. Categories:

Fixes (Precision Pruning)

Review Patterns groups findings, shows evidence, risk and side effects, and lets you approve or reject each one. Apply Global Fixes previews an exact diff first; only approved or high-confidence automatic fixes are applied, each batch is syntax-checked and rolled back automatically if validation fails. Your original upload is never modified; changes happen in a separate working copy.

Cleanup, backups, rollback, download

  • The Cleanup page lists real candidates with sizes and reasons. Select All Redundant selects confirmed, automatically-fixable items.
  • Previews and the final log use the same planning code, so numbers match the real operation.
  • A backup of every touched file is made first. Uncertain, changed-since-scan, rejected or below-threshold items are skipped and listed with the reason.
  • Each run in the history can be rolled back (most recent first; files changed since are detected and block the rollback instead of being overwritten). A patch file (unified diff) is saved per run.
  • Download Cleaned ZIP packages the current working copy.

Validation is syntax-only: Python is parsed, JavaScript/TypeScript is checked for balanced brackets and strings. Your project's own tests are never run, so run them yourself after downloading.

Routes & API

All routes except the landing, login, register and documentation pages require sign-in. Data belongs to its owner: another user's project returns "Access denied" (pages) or 404 (API). POST/PUT/DELETE requests need a CSRF token (X-CSRFToken header or csrf_token field).

Database & migrations

SQLite in instance/database.db. Tables: user, scan, finding, cleanup_run, user_setting, schema_version. Migrations only add columns/tables; old scan rows are kept and marked as legacy.

Security

  • Passwords hashed (PBKDF2); login attempts throttled; safe redirect handling; CSRF protection; security headers.
  • Uploads are stored outside static/ and are never served directly.
  • The GitHub token is encrypted with a key derived from the server secret and never sent to the browser or written to logs.
  • Uploaded code is never executed.

Troubleshooting

  • Page looks unstyled: Tailwind and fonts load from CDNs - an internet connection is required.
  • "Scan interrupted": the server stopped mid-scan; use Re-scan on the project page.
  • GitHub rate limit: save a token in Settings or wait for the reset time shown.
  • Rollback blocked: a file changed after the run; the message names it. Restore manually from the patch or re-run.

FAQ

Why is something "potential"? Static analysis cannot rule out dynamic use. Is my code uploaded anywhere? No: it stays on the machine running DeadCodeX (GitHub import only downloads from GitHub). Can I use it on Linux/macOS? Yes, the same steps work with python3 -m venv venv && source venv/bin/activate.
